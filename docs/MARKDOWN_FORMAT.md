# Markdown format

Every meeting produces up to two UTF-8 files (no BOM, LF line endings): one for notes and one for the transcript. Both start with YAML front matter. Front-matter strings are written as double-quoted, escaped values, so they always parse.

## Filenames

The default template is `{MeetingDate}-{MeetingTitle}.md`, for example `2026-10-26-Client-Requirement-Discussion.md`.

- Unicode letters are kept (`ગુજરાતી-મીટિંગ.md` works). Characters that are invalid on Windows, macOS or Linux become `-`. Windows reserved names (`CON`, `NUL`, …) get a `_` prefix. Names are capped at 120 characters.
- If two meetings would get the same path, the second gets the last 6 characters of its Granola note ID (`…-Standup-bbbbbb.md`). If a file the app did not create already sits at the target path, the same rule applies, so that file is never overwritten.
- A file keeps its path across re-exports and source updates. Only a reassignment to another project or location moves it.

## Notes file

```markdown
---
source: granola
content_type: notes
granola_note_id: "not_1d3tmYTlCICgjy"
title: "Client Requirement Discussion"
meeting_date: "2026-10-26"
meeting_start: "2026-10-26T10:00:00Z"        # when Granola provides calendar times or timestamps
meeting_end: "2026-10-26T10:45:00Z"
source_created_at: "2026-10-26T10:00:30Z"
source_updated_at: "2026-10-26T10:50:00Z"
project: "Motor Dealer App"                   # null when unassigned
project_slug: "MotorDealerApp"
project_id: "8f0c…"
client: "Example Client A"
location: "Project"                           # Project | Unassigned | Shared
classification_status: "Assigned"
classification_method: "Rule"                 # Manual | Rule | Ai | None
classification_rule: "Participant email match"
participants: ["Alice Client", "Kishan Parmar"]
source_url: "https://notes.granola.ai/d/…"
export_role: primary                          # or copy (multi-project exports)
generated_at: "2026-10-26T12:00:00Z"
content_hash: "sha256:…"
---
# Client Requirement Discussion

## Meeting Information
- **Date:** 2026-10-26 10:00 – 10:45 UTC
- **Project:** Motor Dealer App
- **Client:** Example Client A
- **Owner:** Kishan Parmar
- **Participants:** Alice Client (alice@client-a.example), …
- **Source:** [Open in Granola](…)
- **Transcript:** [Client Requirement Discussion — Transcript](<../Transcripts/2026-10-26-Client-Requirement-Discussion.md>)

## Meeting Notes
<!-- Written by the note owner in Granola. -->
…the owner's own notes, verbatim…

## Summary
<!-- Generated by Granola. Stored verbatim from the Granola API. -->
…Granola's summary, with its headings nested one level down…

## Attachments
- [photo att_…](signed URL)
```

Sections whose data is not available are omitted, never invented. In particular there are no "Action Items" or "Open Questions" sections unless Granola's own summary contains them, in which case they appear inside the Summary. If Granola returned neither notes nor a summary, the file says so.

## Transcript file

```markdown
---
source: granola
content_type: transcript
granola_note_id: "not_1d3tmYTlCICgjy"
…same metadata as above…
transcript_segments: 127
generated_at: "…"
content_hash: "sha256:…"
---
# Client Requirement Discussion — Transcript

**Meeting Date:** 2026-10-26 10:00 – 10:45 UTC

**Project:** Motor Dealer App

**Notes:** [Client Requirement Discussion](<../Notes/2026-10-26-Client-Requirement-Discussion.md>)

## Transcript

**[00:00:12] Kishan Parmar (note owner):**

Original transcript text.

**[00:00:35] Alice Client:**

Original transcript text.
```

- Segments stay in source order. Consecutive segments from the same speaker are joined into one paragraph. Words are not changed.
- Timestamps are offsets from the first segment. They are omitted if the source has none.
- Speaker labels, in order of preference:
  1. The name Granola identified.
  2. Granola's diarization label (`Speaker A`).
  3. The owner's name with "(note owner)" for `attribution: me`.
  4. "Other participant" for `them`.
  5. Otherwise "Unknown speaker (microphone / system audio)".
- Granola can record the same speech on both the microphone and system-audio channels, so a phrase may appear twice. This is kept as in the source.
- Markdown or HTML control characters in speech (`<`, `>`, and line-leading `#`, `>`, `-`, `1.` …) are backslash-escaped. Text renders exactly as spoken and is never interpreted as HTML.
- Large transcripts are written in full. A failed transcript retrieval is **never** written as an empty transcript: the transcript record is marked `Failed` and retried.

## Content hash and conflict detection

`content_hash` is the SHA-256 of the whole document, excluding the `generated_at` and `content_hash` lines, with line endings normalised. On each export:

| On-disk state | Source unchanged | Source changed |
|---|---|---|
| Hash matches (not edited) | No write | Rewritten in place |
| Edited by you | Status `LocallyModified`, no write | Status **`Conflict`**, no write |
| Missing (you moved or deleted it) | Status `Missing`, not recreated | Recreated |
| Another file (different `granola_note_id`) | Never overwritten | Never overwritten |

You can resolve a conflict from the meeting page:

- **Keep local**: your file stays, and the record is marked `KeptLocal` until the source changes again.
- **Replace with source**: the file is regenerated.
- **Save conflict copy**: your file stays, and the source version is written next to it as `<name>.conflict-YYYYMMDDHHMMSS.md`.
- **Review**: shows both versions side by side, so you can merge by hand and then keep local.

To regenerate everything regardless of edits, set `conflictPolicy` to `AlwaysOverwrite`, or use **Re-export → force** on a meeting.

## Project files

- `README.md` is created once per project and never overwritten.
- `PROJECT_CONTEXT.md`: only the region between `<!-- granola-pi:generated:start -->` and `<!-- granola-pi:generated:end -->` is rewritten, and only when it changed. Write your own notes above or below it. If you delete the markers, the file is left alone. The generated region lists:
  - the project's meetings, with links to their notes and transcript;
  - recurring participants;
  - lines copied verbatim from Granola summary sections titled action items / next steps, decisions, and open questions, labelled as discussion records rather than confirmed decisions.
- `Unassigned/ReviewQueue.md` lists meetings awaiting review, with the reason and candidate projects for each. It is regenerated after each sync.
